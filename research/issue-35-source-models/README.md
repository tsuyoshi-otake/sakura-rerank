## IRVと責任範囲

**A. 範囲:** `source_model_inputs.py`が認証済み候補からラベルなしtensorへの射影を所有し、
`source_score_outcomes.py`が固定scoreとゲートの決定を所有する。関連2 test、既存v1/r2 encoder/features、
評価指標・統計の公開契約、今回の研究binding/runnerが理解範囲。

**B. 拡大:** 6は候補の固定件数ではなく格納容量だったため、1〜6候補のmaskとpaddingへ対応した。
32文字上限とfloat32 score/float64 marginも照合した。保存sourceは旧訓練cacheの利用許可と異なるため、
その境界を迂回せず、専用のラベルなし射影を追加した。モデル構造や既存の学習/Gold契約は変更0。

**C. 状態と依存:** source/model/旧評価artifactはimmutable。研究runnerが予約・期限・終端を所有し、
全モデルの出力sealを評価の前提とする。モデルfeedにtarget/原文文脈は渡さない。
失敗は既存評価契約のlocal fallbackへ接続し、実行済みnative要求を再生成しない。

**D. 次回:** 同じ固定モデルを別の認証済み候補へ接続する際、入力容量・padding・固定ゲートの意味を
2責務と2 testから確認できる。新しいsourceの独立性・読み/入力単位・Gold根拠は毎回別に必要であり、
今回の原文一致を正解認証へ読み替える理解コストを省略しない。
