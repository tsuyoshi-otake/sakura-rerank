## 監査の固定と範囲

全75,000行の元component、元のbounded input hash、数値model-input hashを連結する。
片方のcohortにない行も橋として保持してから、それぞれの50,000行を完全な成分単位で分ける。

これはラベルを参照しない固定配分であり、出典均衡や統計的独立性の保証ではない。

## 件数を増やすだけでは増えない独立性

| 対象 | 行数 | 記録された成分数 | 最大成分の行数 |

| 共通Wikipedia | 25,000 | 9,976 | 23 |

現行のsource/入力関係で分離できないことを意味する。成分定義を都合よく弱めたり、最大成分を捨てたりしない。

## 一段のOOFだけでは適用器へ漏れる

外側の検証foldを`o`、適用器の訓練例を作る内側foldを`i`とする。
普通のOOF候補モデルは`i`だけを除いて学習するため、`o`を含み得る。
そのスコアで適用器を学習して`o`を評価すると、直接の行分割が別でも依存が戻る。
合成テストで「iだけを除外すると通過、oとiを除外すると拒否」を再現した。

| 用途 | 順位モデルが学習できるfold | スコアを作るfold |
|---|---|---|
| 外側oの検証候補 | 全体からoを除く | o |
| 外側oの適用器の訓練候補 | 全体からoとiを除く | i（i≠o） |
| 最終適用器の訓練候補 | 全体からiを除く | i |
| 最終順位モデル | 許可された全train | 独立calibration / 最終Testは別工程 |

これは直接fitだけの条件ではない。初期モデル、蒸留教師、モデル選択、特徴の前処理にも同じ除外が必要。
`gate_oof.score_exposure`はこれらの親依存をたどり、fit/selectionとの交差、欠損来歴、循環を拒否する。
APIの通過は認証済みの記録に対する整合性であり、未知の原出典関係やGold品質を自己認証しない。

5-foldでは外側モデル5、内側20役割、最終モデル1の計26 fits。
内側の除外集合`{o,i}`と`{i,o}`が、初期値/教師・前処理・seed・提示順・最適化設定まで完全同一なら、
10種類の内側fitを共有でき、**順位モデル16 fits、適用器6 fits**に減らせる。
違う条件を同じ除外集合というだけで共有しない。各fitの実byte identityが必要。
固定scheduleは集計JSONとprivate `nested-schedule.json`に保存したが、実行許可はfalse。
