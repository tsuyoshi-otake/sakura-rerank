## 同じ予算で増やせる対比

二つのliteral原表記に各二つの左文脈、四つの異なるsource componentを要求した。componentは既存の作品/著者/段落/近重複/同入力関係の閉包であり、統計的独立性そのものを保証しない。文書IDだけが異なる場合も別計数した。既存selectorによる保守的な証拠なので、全可能組合せ数ではない。

| 5万件の選択案 | 固定control | 対比を先に予約 |
|---|---:|---:|
| Wikipedia / 青空 | 25,000 / 25,000 | 25,000 / 25,000 |
| 4文書の対比 | 435読み | 1,290読み |
| 4 source componentの対比 | 424読み | **1,286読み** |
| 対比を示せる読み群内の全行 | 6,640 | 13,902 |
| 複数原表記の読み群内の行 | 12,253 | 15,928 |
| 単一原表記の読み群内の行 | 37,747 | 34,072 |
| 読みの種類 | 16,233 | 15,603 |
| 読み別多数表記の学習内一致 | 47,008 / 50,000 | 45,262 / 50,000 |

固定controlは履歴更新後のeligible行を各出典のstable-ID順で採取する。対比案は読みhash順に1組ずつ4行全体を予約し、同じ出典quotaの残りを同じstable-ID順で補う。1,286組・5,144行を予約でき、quota超過で捨てた組は0。両案の共通行は46,616、入れ替わった行は各3,384。事前の「同一件数/出典比率で対比を2倍以上」という容量条件は通過した。

代償として読みの種類は630少ない。対比の増加だけで精度向上を断定せず、将来の固定比較では未知の読みへの適用範囲も扱う。#47の439組は旧50,000行の4文書条件であり、今回の履歴更新済み4-component control424組とは同一条件の数値ではない。旧学習集合は変更していない。

原表記の比較写像で衝突する対比は対比案の10組にあった。これは許容表記の認定ではない。全162,502行には漢字隣接26,391、漢字/仮名隣接83,712、引用符が見える行29,482、ASCII文字を含む対象1,227があった。これらは重複する確認フラグであり、誤り率や自動除外件数ではない。

## 原文へ戻って回収できた証拠

従来の`aozora_paragraphs`はルビを除去し、`GrowthExtractor`はその後の辞書一致対象へ辞書読みを付けていた。新しい[原注釈回収plan](ruby-plan-v1.json)を実行前に凍結し、既存の訓練側546作品だけを開いた。新規コーパス取得・評価文書の読取り・新対象の追加は行っていない。

原zipのreceipt、展開したCP932 bytesのsource revision、旧cleanerの全段落との一致を検証した。元stable-IDを作った段落/文番号・開始/終了位置を再構成し、**58,813行すべてで原位置、左文脈、対象文字列が一致**した。原文とルビの文字列はGit/logへ出さず、位置・hash・判定状態を追加sidecarへ保存した。

| 元の青空訓練行とのルビの関係 | 件数 | 全58,813行に占める割合 |
|---|---:|---:|
| 範囲が一致し、読みも一致 | 1,388 | 2.3600% |
| 範囲が一致し、辞書読みとは不一致 | 801 | 1.3619% |

一致1,388行のうち、従来の実候補条件も満たすのは1,360行。この集合だけで2表記×2文脈×4 source componentを確認できた組は**0**だった。対比案の予約5,144行中、青空2,259行では、読み一致92、不一致46、範囲違い93、ルビなし2,027、記法未解決1。予約した対比で4行すべての読み証拠が揃った組も0だった。

801件は「原注釈と辞書の証拠不一致」であり、801件すべてが言語学的な誤ラベルだとはしていない。旧仮名、表現意図、語義や名称等の解釈は未認証のまま残る。ルビ一致も、実IME入力単位・語義の違い・許容表記・独立Goldを認証しない。部分ルビから対象の読みを切り出して割り当てていない。

記法の範囲は[青空文庫の原注釈仕様](https://www.aozora.gr.jp/annotation/etc.html)と[テキスト版の点検指針](https://www.aozora.gr.jp/KOSAKU/textfile_checklist/)を2026-11-05に確認した。実装は明示的な区切り、および仕様に沿う漢字列と5特殊文字の暗黙範囲に限定する。他文字種の暗黙範囲は推測しない。片仮名→平仮名は読み比較にのみ用い、元文字列を維持し、長音・歴史的仮名遣い・表記の正規化はしない。

## IRV・検証済みの学び

A. 責務は訓練側対比の選択容量、既存出典の注釈/位置証拠、認証・再計数・永続化。入口4 scripts、純粋処理2 modules、関連3 test filesと固定plan/品質仕様を中心に扱った。全回帰は571件。

B. 範囲拡張は二つ。四文書でも著者/近重複で同じ成分になるためcomponent条件を別計数した。また原recordに注釈/位置が残らないと判明したため、事前に追加planを凍結して原zip・旧cleaner・stable-ID生成規則まで調査した。これが必要だったのは、候補一致や文書数を教師品質と混同しないため。モデルや本番実装へは拡張していない。

C. `contrast_capacity.py`が容量・候補状態・選択案、`aozora_ruby_evidence.py`が原注釈と元位置の復元を所有する。scriptはhash認証・sourceアクセス・新sidecarの永続化を所有し、旧ラベル/分割の所有権は移さない。旧cleaner/文分割への依存は、その凍結挙動との完全一致が必要なためで、parity検証で契約を監視する。production/model/runtimeの依存変更はない。

D. 次の採取Issueは、この入口から出典独立性、原注釈の対応範囲、元の読みとの不一致を再利用できる。LM学習や過去モデルの内部を再読せずにsource evidenceを検証できる。新たに理解が必要なのは「注釈から先に対象を取る」新母集団と全履歴隔離、意味/表記/IME境界に残る未認証軸。検証済みの学びは、ルビ除去後の辞書一致だけでは注釈証拠を復元済み扱いできないこと、四文書と四componentは別指標であること、manifest hashは手で転記せず原artifactから計算して固定すること。
