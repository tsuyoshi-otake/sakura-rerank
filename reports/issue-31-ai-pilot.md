# #31 自律実行した1,000件AI pilot

2026-11-04。親Issue #1、#31、関連#32。**1,000件のAI初回確認と10件の自己訂正を完了した。人手判定・独立二重判定・独立Test・Gate A合格は成立していない。**

所有者の「自律的に全作業」の依頼を受け、担当者の割当を待つ運用から、別記録のAI監査へ進めた。既存の人手packet、方針、空の人手台帳は変更していない。元ラベルへの適用、本格Gold構築、#33/#34/#35の実装、再学習、閾値変更は行っていない。安全性基準は0.25%のまま。

## 結果と意味

[集計JSON](issue-31-ai-pilot-v1.json)は40個の初回判定batchと10個の自己訂正eventのhashを固定する。

| 最終AI分類 | 件数 | 1,000件に対する割合 |
|---|---:|---:|
| 原goldを一意に妥当と判断 | 807 | 80.7% |
| 同じ意図の複数表記を提示 | 113 | 11.3% |
| 文脈不足・意図や固有名詞を限定できない | 64 | 6.4% |
| 読み不整合の疑い | 3 | 0.3% |
| その他の要確認 | 13 | 1.3% |

その他13件は抽出ノイズ5件・未解決8件。別候補への確定的なgold修正提案0件、確定的な分割誤り0件。未解決には、語途中の入力、固有名詞の切断、専門用語の読みなどの疑いを残している。0件はその種類の問題が存在しないことの証明ではない。

**80.7%はラベル正解率でもモデルAccuracyでもない。** 113件の許容表記も確定Goldではない。今回のAI判定は一人の助手による候補集合内の暫定的な解釈であり、候補外の正解やすべての同値表記を網羅しない。従来の3,576件AI監査の問題率4.87%とは、対象・抽出単位・方針・判定者が異なるため増減を比較しない。

初回は一意803・表記同値113・文脈不足63・ノイズ9・分割3・読み4・未解決5だった。再確認で10件を訂正した。

- 読み誤りとした1件は、私自身が読みを取り違えた誤指摘だったため撤回した。
- 読み不整合を伴う分割指摘1件は、既存方針の優先順位に従って読み側に分類し直した。
- 語途中の入力2件と専門用語の読み1件は、提示証拠だけで欠陥と断定できず未解決に変更した。
- 原文の不備が疑われても対象語の判断を妨げない4件は、ノイズとラベル欠陥を区別して判定し直した。文脈のない人名1件は、一意判断から保留へ変更した。

自己訂正は初回記録を残した追記であり、独立した第二判定ではない。10件という数はAIの誤り率ではなく、再確認で変更した件数にすぎない。

## 方法・限界

使用したのは既に固定されたtrain由来1,000入力群の同一packet。選択母集団はtrain 12,467 distinct input groups。dev、final holdout、モデルscore、変換器順位、将来・右文脈を判定に使っていない。元のsource goldは提示されているため、原ラベルへのアンカリングは残る。候補は表記順で提示した。

各25件を助手が読み、verdict・根拠・許容する候補表記を個別に指定した。未確認例への既定のvalid付与は行っていない。最初の21batchでは左文脈・読み・表面・全候補を確認し、後から複数segmentの例を追加確認した。22batch以降はsegmentも併記して確認した。これはsource/readingの独立した正解照合ではなく、AI言語判断である。

[AI方針v1](../research/gold-pilot-ai-policy-v1.json)は既存の人手方針とは別hash。単なる発音どおりの仮名候補を無条件に同値とせず、数字、送り仮名、新旧字体、略記等を個別に記録した。ただし、正式名称・引用で許容する旧字体、原語表記、慣用表記の範囲には判断の余地が残る。今後の固定Goldに、この113集合を自動で採用してはならない。

同じ助手による再確認では独立性も外部の正解も得られないため、認証されたラベル品質の95%信頼区間は算出しない。単なるAI分類数にWilson区間を付けても99.5%/99.0%の品質要件を検証したことにはならない。独立holdout valid countは0であり、最終3,000件要件は未達。

## 優先順位と次段階の判断

1. **表記と意味の判定方針を具体化する。** 同値113件と文脈不足64件を分け、引用・正式名称・旧字体・仮名書き・原語表記の扱いを仕様にする。期待効果は誤評価の削減でありモデル精度の増分は未測定。次回の個別再確認対象は177件。現行データへの適用は別判断。
2. **読みに関する3件と要確認13件を優先して出典・境界検証する。** 候補中に原goldがあっても自然な入力かは別問題。期待効果は不正な教師信号の除去候補を絞ること。検証対象16件で、元sourceの訂正を伴わない根拠整理から始められる。新しい読みを推測して正解化しない。
3. **評価設計は固定入力単位から組み立てる。** #32の交差重複8群を新しいsplit設計で防ぎ、calibration/testの分離と一度だけの最終評価を維持する。今回のpilotを独立Testへ転用しない。#35の実装は本pilotの完了を理由に開始しない。
4. **ゲート・モデルの比較はその後。** 救済48件を手掛かりにする方針は維持するが、今回の判定から閾値を選ばない。#34の独立calibration、95%区間、0.25%基準と#33の仮説ごとの実験は未実施。

このpilotにより、AI監査・履歴・集計を担当者割当なしで進められることは確認できた。一方で、独立した正解照合、二人の人間の一致率、裁定所要時間、最終Gold品質は測れていない。本格Goldを今ここで認証できるという結論にはならない。

## Scopeと検証済みの学習

A: 既存packet契約・ラベル方針・human拒否契約を参照し、AI専用モジュール1件、契約test1件、方針と集計・報告を追加した。
B: 人手割当待ちを解除するため、既存human台帳へAIを混ぜるのではなく、別のprovenance契約が必要になった。専門語の読みと入力境界の解釈は提示証拠の限界として残した。
C: AI判断stateはimmutable batchとhash-linked自己訂正台帳が所有する。既存の人手判定・source・モデル・Gateの状態所有者と契約は変更していない。書込み先を元datasetへ接続していない。
D: 次回のAI監査はこの報告・AI方針・単一モジュールとtestから再開できる。AI単独完了は独立Gold品質保証ではない、自己訂正は第二判定ではない、という区別を全件成功テストでも検証した。Windowsで日本語packetを表示するPythonには`-X utf8`を明示する。初回表示の文字化けは再表示してから判定し、文字化けした表示に依存した判定は行っていない。
